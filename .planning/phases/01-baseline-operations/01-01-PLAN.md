## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator configuration -> Go/Rust processes | Potential secrets enter runtime configuration and startup validation. |
| host/public network -> Compose services | Untrusted traffic may reach the public Go port but must have no route to Rust. |
| repository -> runtime environments | Committed examples cross into ignored per-environment secret files. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `loadConfig` and example files | high | mitigate | Key-only startup errors, non-secret examples, ignore-contract tests, and pre-bind validation. |
| T-01-02 | Elevation of Privilege | Compose Rust service | high | mitigate | No Rust `ports`, private `internal: true` network only, plus resolved-model assertion. |
| T-01-03 | Denial of Service | `/healthz` | low | accept | Constant local response performs no dependency call; residual request-volume control belongs to deployment ingress. |
| T-01-SC | Tampering | existing Go/Rust/container inputs | high | mitigate | Add no dependency in this plan; preserve lockfiles and pin the numeric Go builder image selected by a green test. Any dependency addition must stop for package-legitimacy review. |
</threat_model>
