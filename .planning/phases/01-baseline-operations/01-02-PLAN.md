<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tool registries/container registries -> developer and CI | Tool binaries and images become executable build inputs. |
| repository lockfiles -> package managers | Dependency graphs must remain immutable during verification. |
| CI environment -> logs/artifacts | Version diagnostics are public operational data; runtime secret values must never be emitted. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-02-01 | Tampering | compiler and CLI resolution | high | mitigate | Resolve through official images/installers, record numeric patches only after a green run, verify Supabase/Compose release checksums, and enforce exact matches before tests. |
| T-01-02-02 | Tampering | Cargo/npm dependency graph | high | mitigate | `cargo test --locked`, `npm ci`, immutable lockfiles, and no update command in the verifier. |
| T-01-02-03 | Information Disclosure | version gate and CI diagnostics | medium | mitigate | Print tool names and expected/actual versions only; never dump the environment. |
| T-01-SC | Tampering | npm/Cargo execution | high | mitigate | No new package is installed beyond lockfile-declared existing dependencies; `npm ci` and Cargo locked mode fail on graph drift. Any dependency change must stop for the package-legitimacy gate. |
</threat_model>
