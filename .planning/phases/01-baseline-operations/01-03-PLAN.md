<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external client -> TLS-terminating ingress -> `web` | The only permitted production path for externally reachable application traffic. |
| `web` -> private network -> `rust-service` | Trusted server-to-server path; Phase 1 enforces reachability, not the later Rust API contract. |
| operator secret injection -> Compose/Supabase config | Real environment values must remain outside source control and rendered configuration output. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-03-01 | Elevation of Privilege | environment overlays | high | mitigate | Resolve every overlay and assert Rust has no published port/public network membership. |
| T-01-03-02 | Information Disclosure | Compose and Supabase configuration | high | mitigate | Environment references only, ignored runtime files, non-secret CLI config, and no value-dumping diagnostic command. |
| T-01-03-03 | Tampering | deployment image selection | medium | mitigate | Staging/production use immutable versioned images and rollback by recorded digest. |
| T-01-03-04 | Denial of Service | health and restart configuration | low | accept | Constant Go health check and bounded restart policy cover baseline operations; capacity controls belong to the selected ingress platform. |
| T-01-03-05 | Spoofing | production ingress | high | mitigate | Require TLS termination at an ingress attached only to Go and require the eventual provider to prove that routing contract. |
| T-01-SC | Tampering | container builds and existing lockfiles | high | mitigate | Pin compiler/base image versions, add no application dependency, and retain locked npm/Cargo inputs. Any package addition requires legitimacy review. |
</threat_model>
